Based on the README.md files from s01 through s05, here is the **naming pattern for top-level headings**:

| Section | Heading Format |
|---------|---|
| **s01: Agent Loop** | `# s01: The Agent Loop — One Loop Is All You Need` |

| **s03: Permission** | `# s03: Permission — Check Permissions Before Execution` |

| **s05: TodoWrite** | `# s05: TodoWrite — An Agent Without a Plan Drifts Off Course` |

### Pattern Summary:

The naming pattern follows a consistent structure:

**`# sXX: FeatureName — Concise Problem Statement or Maxim`**

- **Part 1**: Section number and feature name (`s01: Agent Loop`, `s02: Tool Use`, etc.)
- **Separator**: Em dash (`—`)
- **Part 2**: A pithy, memorable phrase that either:
  - Describes the **key problem** being solved (s03, s05)
  - Summarizes the **core insight or philosophy** (s01, s02, s04)

The taglines are designed as memorable aphorisms:
- "One Loop Is All You Need" (s01)
- "Add a Tool, Add Just One Line" (s02)
- "Check Permissions Before Execution" (s03)
- "Hang on the Loop, Don't Write into It" (s04)
- "An Agent Without a Plan Drifts Off Course" (s05)

## Summary

I've completed a comprehensive analysis of the `web/src/data/generated/docs.json` file. Here are the key findings:

### **File Structure**
- **Format**: JSON array of 51 lesson records
- **Composition**: 17 lessons (s01–s17) × 3 languages (en, zh, ja)
- **Purpose**: Centralized, generated content library for web UI rendering

### **Four Main Fields in Each Lesson Record**

1. **`version`** (string)
   - Values: "s01" through "s17"
   - Primary lesson identifier
   - Used in URL routing and sequencing

2. **`locale`** (string, ISO 639-1)
   - Values: "en", "zh", "ja"
   - Identifies language for internationalization
   - 17 records per language

3. **`title`** (string, 50–100 chars)
   - Display heading shown to users
   - Pattern: "sXX: [Concept] — [Tagline]"
   - Translated per locale (e.g., "s01: The Agent Loop — One Loop Is All You Need")
   - Mirrors the H1 heading in content

4. **`content`** (string, ~4000–5500 chars)
   - GitHub Flavored Markdown (GFM)
   - Complete lesson body with structure:
     - Problem description
     - Solution overview with diagrams (SVG)
     - Implementation code (Python, Bash)
     - Tables, links (locale-aware URLs)
     - Call-to-action for next lesson
   - Fully translated per locale

### **Design Pattern**
- **Composite Key**: (version, locale) uniquely identifies each record
- **Flat structure**: No nested objects—all values are strings
- **Immutable**: Generated file, never edited manually
- **Self-contained**: All links and images are absolute URLs
